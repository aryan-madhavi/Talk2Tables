Core Capabilities

Built for industrial
environments

Every feature is designed around the constraints and risks of real manufacturing operations — where a wrong query can have serious consequences.

💬
Natural Language Queries
Type questions in plain English or Hindi. Talk2Tables translates intent into accurate, schema-aware SQL — supporting joins, aggregations, filters, and subqueries.
NLP → SQL
🛡️
Write Operation Safety
UPDATE and DELETE are never auto-executed. The system shows a preview with risk level, estimated affected rows, and requires explicit user confirmation.
High Risk Guard
🔀
LLM Fallback Chain
Primary: OpenRouter (Qwen2.5-Coder-32B). Falls back automatically through Groq → Gemini → local Ollama. Zero downtime from provider outages.
Resilient
🔄
Self-Correcting Agent
When generated SQL fails validation, the agent retries up to 2 times — feeding the exact error reason back to the LLM so it can self-correct.
LangGraph
📋
Schema Understanding
Reflects live database schema via SQLAlchemy. Supports uploaded documentation (PDFs, Word docs) to understand domain-specific business context.
SQLAlchemy
🔐
RBAC + Firebase Auth
Four-tier role hierarchy: analyst → power_user → db_manager → admin. Firebase ID tokens with custom role claims. AES-256-GCM encryption for credentials.

↳ WRITE_OP branch
UPDATE / INSERT / DELETE returns a preview with risk level and estimated affected rows. Execution only happens on explicit approval via a separate /execute endpoint.
↳ CLARIFY branch
When the query is ambiguous, the LLM returns a clarifying question instead of SQL. The answer feeds into the next turn's context automatically.
↳ RETRY branch
If validation fails, the agent retries up to 2 times — passing the specific error reason back to the LLM so it can self-correct. Structured error returned after 2 failures.

10 stages before
any query runs

LLM Directive Check

Write Operation Preview

Before any UPDATE or DELETE runs, the user sees exactly what SQL will execute, how many rows are affected, and the risk level. Nothing executes without a deliberate click.

⚠️ Write Operation — Confirmation Required 
UPDATE sensors
SET status = 'out_of_service'
WHERE zone = 'B'
  AND last_reading_date < '2026-01-01';
⚠ HIGH RISK ~14 rows affected UPDATE

This will modify records in the sensors table. Review the SQL carefully before confirming.
